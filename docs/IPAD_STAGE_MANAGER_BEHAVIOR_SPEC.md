# iPad Stage Manager 功能与交互规格（Android StageLab 对照版）

> 版本：1.0
> 研究日期：2026-11-20
> 目标设备：OPPO Pad mini / ColorOS 17 / Android 17
> 工程：`E:\\codex\\pad-stage-manager`
> 当前代码基线：`e3fbb3f`
>
> 本文将 Apple 官方 iPad Stage Manager 行为、iPadOS 相邻多窗口能力、StageLab 当前实现和项目额外要求分开描述。不得把 Mac Stage Manager、iPadOS Windowed Apps 与 iPad Stage Manager 混成一个未经区分的产品定义。

## 1. 产品定义和范围

本项目要复刻的是 **iPad 上的 Stage Manager（台前调度）**：

- 一个当前活动的工作区（Stage）。
- 左侧最近使用的应用/应用组列表。
- 当前工作区中一个或多个真实应用窗口，可自由排列、重叠。
- 底部 Dock，用于启动和切换应用。
- 应用组切换、窗口拖放、窗口最小化/关闭/恢复。
- 通过触控手势、Dock、最近应用栏完成工作流切换。

这里的“工作台模式”定义为：**一个 Stage Group 就是一个工作台/工作区，包含一个或多个真实应用窗口；多个工作台保留各自的窗口集合、位置、层级和运行状态。点击左侧某个工作台，切换整个工作台，而不是只启动一个 Activity。**

### 1.1 必须区分的三个概念

| 概念 | 含义 | 本项目关系 |
|---|---|---|
| iPad Stage Manager | 左侧最近应用/组 + 中央 Stage + Dock；支持组管理 | 核心复刻目标 |
| iPadOS Windowed Apps / 通用窗口系统 | 多窗口、窗口菜单、排列布局、菜单栏等 | 相关能力，可作为扩展，不应冒充 Stage Manager 核心 |
| macOS Stage Manager | Mac 的桌面/窗口组织方式 | 不是本项目目标，不得照搬 Mac 行为替代 iPad 触控逻辑 |

Apple 官方 iPad 用户指南当前分别描述 Stage Manager、Windowed Apps、窗口菜单、App Exposé 和外接显示器。功能清单应按平台实际支持能力映射。

## 2. iPad Stage Manager 核心界面

### 2.1 中央工作区（Stage）

- 当前活动的应用组显示在中央工作区。
- 同一个工作区可以同时包含多个应用窗口。
- 窗口允许自由排列、部分重叠，前后层级明确。
- 当前被操作的窗口获得焦点并提升到前层。
- 切换工作区时，整个旧工作区退到最近应用列表，新工作区整体进入中央区域。
- 每个工作区的窗口几何、z-order、窗口状态应分别保存。
- 不允许每次切换都重启应用；必须优先保留原 Task、进程、Activity 状态和 Task ID。

### 2.2 左侧最近应用 / 工作台列表

- 默认在宽屏/横屏显示，是工作台切换的主要入口。
- 每张卡片代表一个最近使用的应用或应用组；一个应用组可含多个窗口。
- 点击卡片即可切换到对应应用组。
- 切换后，原活动组进入最近列表，目标组进入中央工作区。
- 最近列表按最近使用时间排序。
- 当前活动组不应重复显示在最近列表中。
- 支持最近列表自动隐藏；从左边缘滑入重新显示。
- 列表需要能够滚动，不能因为屏幕高度或组数增加而裁掉工作台。
- 卡片预览至少清楚显示组内应用图标/窗口构成；项目额外要求在技术允许时保持真实实时画面，不允许用定时截图冒充实时预览。

### 2.3 底部 Dock

- Dock 位于屏幕底部中央，圆角半透明背景，悬浮于工作区之上。
- 左侧为用户固定的常用应用；右侧可展示最近/建议应用；最右侧提供应用库入口。
- 图标为真实应用图标，图标尺寸、间距、圆角和 Dock 高度保持一致。
- 点击图标：启动应用，或恢复/切换到已有应用窗口。
- 长按图标：显示可用快捷菜单，例如 New Window、Show All Windows（仅对支持多窗口的应用显示）。
- 长按拖动图标到中央工作区：将应用加入当前工作台；拖动落点决定初始窗口位置。
- Dock 可按设置自动隐藏；从底部边缘轻扫显示。
- Dock 不应塞入“应用组开关、重整、演示、全部关闭、退出 StageLab”等开发者操作。
- 模式退出应由系统返回/专门控制入口/通知动作等独立路径完成，不要把危险的“全部关闭任务”按钮伪装成 Dock 项。

### 2.4 圆角、窗口层次和外观

- 所有真实应用窗口都必须具有统一的 iPad 风格圆角，包含四角，不只是标题栏圆角。
- 窗口有轻微阴影、焦点描边/层级反馈；非焦点窗口仍可见。
- 标题栏与内容区必须组成一个连续的圆角窗口，不允许顶部圆角、下方内容仍是方形。
- 圆角必须作用于真实 Task Surface 或通过不影响原生输入的窗口装饰层实现；Compose 对 StageHost 自己的 UI 使用 `clip(RoundedCornerShape)` 不会裁剪系统上方的独立 Task 窗口。
- 不能用截图或 Bitmap 重绘应用内容来做圆角。
- Apple 官方指南描述窗口行为，但不规定圆角像素值；圆角半径应通过 iPad 视觉参考在目标设备上实测校准。

## 3. 应用组（Stage Group）完整逻辑

### 3.1 创建工作台/应用组

- 从左侧最近应用列表，将一个应用窗口拖入中央工作区，可把它加入当前组。
- 从 Dock 将应用图标拖入中央工作区，可将该应用加入当前组。
- 如果用户从 Dock 点击一个尚未运行的应用，则在当前活动组中启动新窗口。
- 如果当前没有活动组，则自动创建一个组并放入该应用。
- 同一应用的多个窗口只有在应用本身/Android Activity 支持多实例或多窗口时才创建；不支持时不能通过重复启动同一 Launcher Activity 伪造多个窗口。

### 3.2 切换工作台

- 点击左侧某个最近应用组卡片。
- 点击 Dock 中应用图标：若该应用已有窗口/组，应优先恢复或切换到已有窗口/组；若没有，按规则加入当前组或创建新组。
- 底部上滑并停顿，显示任务/工作台切换视图。
- 屏幕底部边缘单指左右滑动，切换最近工作台。
- 四指或五指左右滑动切换工作台（若 Android 系统手势冲突，采用应用内可控替代手势，不得破坏系统导航）。
- 点击切换必须是第一优先级；横屏左侧工作台卡片必须始终可见且可点击，不得要求用户先点 Dock 中一个隐藏的“应用组”按钮才能找到工作台。

### 3.3 从工作台移除窗口

- 将窗口向左拖出中央工作区并拖入最近应用列表：从当前组移除，保留该窗口/任务，出现在最近列表中。
- 最小化组内窗口：该窗口从当前组移除，返回最近应用列表；窗口状态保留，可再次拖入其他组。
- 关闭窗口：关闭对应真实 Android Task；只有系统确认 Task 已关闭后，才从模型移除。
- 删除一个工作台不能误杀其他工作台中的任务。
- 只有用户明确关闭某个窗口或确认清空某组时，才执行对应任务关闭。

### 3.4 组切换状态机

切换工作台时按以下顺序执行：

1. 锁定当前手势/窗口操作，防止并发几何修改。
2. 保存旧活动组的所有窗口几何、z-order、焦点和最小化状态。
3. 将旧组窗口按平台能力停放/隐藏，保留 Task 和进程。
4. 更新最近组顺序与 activeGroupId。
5. 将目标组窗口恢复到各自几何位置，恢复窗口层级。
6. 聚焦目标组最近活动窗口。
7. 播放组切换动画。
8. 更新左侧最近组列表和 Dock 状态。
9. 写入持久化存储。

切换不能只改 UI 的 activeGroupId；必须保证真实系统 Task 的 bounds、可见性、焦点与模型一致。

## 4. 单窗口操作与窗口控制

### 4.1 移动

- 从窗口顶部/标题栏拖动窗口。
- 窗口跟随手指移动，边界限制合理。
- 释放时保留最终位置。
- 窗口拖到左侧最近应用区域时触发“从组移除/回到最近列表”。
- 拖到另一个组卡片时触发“移动到该组”，并显示明确的拖放目标反馈。
- 拖动过程中不能吞掉内容区域的原生触摸；标题栏是专用手势区域。

### 4.2 缩放

- 支持四角与四边缩放；至少右下角缩放必须准确。
- 支持最小/最大尺寸限制。
- 拖动边缘时只有对应边变化，拖动角时宽高同时变化。
- 横屏/竖屏切换后按归一化几何恢复，避免窗口跑出屏幕。
- 不允许仅在 UI 画框而不改变真实 Task bounds。

### 4.3 窗口控制菜单

iPad 常见窗口控制包括：

- Close：关闭窗口。
- Minimize：最小化窗口。
- Zoom / Full Screen：窗口最大化或恢复到全屏/大尺寸。
- 长按窗口控制按钮：显示更多排列/窗口选项。
- 双击窗口顶部：在启用相应设置时缩放到全屏。
- 从窗口顶部向下拖动并停留，再快速向上甩动：可返回全屏（具体手势以设备实际实现为准）。

StageLab 当前只有红色关闭与黄色最小化控制，缺少完整的 Zoom/Full Screen、控制菜单和双击标题栏逻辑。

### 4.4 焦点与前后层级

- 点击窗口内容区时，窗口成为焦点并置于前层。
- 点击窗口标题栏也应聚焦并允许拖动。
- 焦点窗口有明确但克制的视觉反馈。
- 同组多个窗口可重叠，点击被遮挡窗口的可见部分应将其提到前层。
- 组切换必须恢复之前的窗口前后顺序。
- 焦点变化不能意外把 StageHostActivity 提到所有任务上方。

## 5. iPadOS 相邻多窗口功能（作为扩展能力）

这些功能与 Stage Manager 紧密相关，但部分属于 iPadOS 的通用窗口系统，不应全部混成 Stage Manager 核心验收。

### 5.1 多窗口同应用

- 对支持多窗口的应用（例如 Safari、Notes、Files 等），长按 Dock 图标可选择 New Window。
- 可将同一应用图标拖到已有同应用窗口上，创建另一个窗口（应用支持时）。
- 不同窗口必须有不同的稳定 windowId 和各自 taskId。
- 不能假设所有 Android 应用都支持同一应用多实例；必须探测能力并对不支持的应用禁用对应入口。

### 5.2 App Exposé / Show All Windows

- 对某个应用显示其全部打开窗口。
- 可从 Dock/应用菜单或任务切换视图进入。
- 选择一个窗口后恢复该窗口。
- 当切换到存在隐藏窗口的应用时，可显示“查看所有窗口”的提示入口。

### 5.3 菜单栏（iPadOS 26+ / 相关窗口模式）

- 在 Stage Manager 或 Windowed Apps 模式下，系统可显示当前应用菜单栏。
- 用户可点击状态栏左上角应用名称或从屏幕顶部手势调出菜单栏（随 iPadOS 版本而异）。
- Window 菜单可包含 Move & Resize、Enter Slide Over、New Window、Show All Windows、Enter Full Screen、Minimize、Move to Display。
- Android 第三方应用不能直接给所有外部应用注入真正的 iPadOS 菜单栏；可评估提供兼容的全局窗口菜单，但必须标记为 StageLab 自有实现。

### 5.4 外接显示器

- iPad Stage Manager 在特定型号上支持把应用窗口移动到外接显示器。
- 对 OPPO Pad mini，先检查 Android/ColorOS 是否支持独立 Display task/window 管理。
- 未经真机验证，不把外接显示器支持列为核心承诺；作为后续 P2。

### 5.5 键盘、鼠标和触控板

- 支持外接键盘时，提供常用窗口切换/任务概览快捷键。
- 支持鼠标/触控板时，标题栏拖动、缩放手柄、Dock hover/点击、窗口焦点应正常工作。
- 不要把 iPad 专有 Command/Globe 快捷键直接假设成 Android 可拦截的全局快捷键；按 Android 可用输入机制设计映射。

### 5.6 Picture in Picture

PiP 是 iPadOS 的独立多任务能力，不是 Stage Manager 工作台本身。Android 已有原生 PiP 机制，应尽量保持系统原生 PiP，不需要在第一阶段自己重写。

## 6. 自动隐藏和边缘手势

| 功能 | iPad 行为 | StageLab 目标 |
|---|---|---|
| 最近应用栏自动隐藏 | 可设置自动隐藏；左边缘滑入显示 | 横屏默认显示；用户可开启自动隐藏；左边缘滑入恢复 |
| Dock 自动隐藏 | 可设置自动隐藏；底部边缘轻扫显示 | 保留底部手势和动画 |
| 工作台切换 | 点击最近组/Dock；底部边缘滑动；多指滑动 | 横屏点击为必需，手势逐项实现 |
| 任务概览 | 底部上滑并停顿 | 提供应用组/窗口概览视图 |
| 系统 Home/Back | 由系统管理 | 不抢占 Android 系统导航，提供兼容映射 |

## 7. 横屏与竖屏布局规格

### 7.1 横屏（OPPO Pad mini 的主要验收模式）

横屏是本项目的优先使用形态：

- 左侧最近工作台列表默认常驻。
- 每张工作台卡片必须可以直接点击切换。
- 左侧栏应有足够宽度，显示真实动态预览、组内应用图标/数量和焦点信息。
- 中央工作区必须明显大于侧栏，支持多个圆角窗口自由排列与重叠。
- Dock 固定在屏幕底部中央。
- Dock 和系统导航区域不能遮挡应用窗口的可交互内容。
- 多工作台超出屏幕高度时，左栏可滚动。
- 切换工作台后，旧组缩入/移入左栏，目标组进入中央工作区，不能只变换一个标题或 activeGroupId。

### 7.2 竖屏

- 竖屏下中央工作区仍然优先显示当前窗口。
- 左侧最近组列表可以采用窄栏或自动隐藏抽屉，避免压缩工作窗口。
- 左边缘手势可以唤出最近组列表。
- Dock 根据宽度调整可见图标数量，支持横向滚动/溢出入口。
- 不允许复用横屏固定尺寸导致窗口被裁切或工作台卡片不可点击。

### 7.3 屏幕旋转

- 旋转不应丢失窗口、组、焦点和任务。
- 每个窗口用归一化几何保存，并在新 viewport 下重新计算。
- 横竖屏布局可以不同，但不能把原来组内窗口拆散或错误地分配到其他组。
- 切换过程需要暂时冻结几何同步，防止旋转中间状态覆盖已保存布局。

## 8. StageLab 当前代码审查：已存在与缺失

当前 HEAD：`e3fbb3f`，工作区干净。用户提供的最新真机截图为竖屏单窗口：窗口内容四角方形、左侧工作台栏不可见、底部 Dock 显示少量图标和“应用组/应用库/退出”操作。

### 8.1 已存在的真实基础

- Shizuku Shell UID 2000 真实 Task 管理。
- FREEFORM Task 真实窗口、实时系统合成和原生输入/IME。
- `StageSession / StageGroup / StageWindow / WindowGeometry` 数据模型。
- `StageWorkspace.activateGroup()`：已有基础点击切换工作台逻辑。
- `StageWorkspace.moveWindowToGroup()`：已有模型层跨组移动函数。
- 窗口标题栏/边缘/角落 Overlay 拖动和缩放。
- Dock 应用点击启动、长按拖动进入工作区。
- 组卡片实时预览通过真实 Task 窗口合成，不使用截图。

### 8.2 当前明确缺口

| 用户观察/功能 | 代码证据 | 结论 |
|---|---|---|
| 窗口没有四角圆角 | `ChromeOverlayView` 只绘制圆角标题条；没有真实 Task Surface corner radius 或四角 mask | 真实应用内容仍是方角 |
| 看不到工作台列表 | `WorkspaceState.railVisible=false`；`StageWorkspace.railVisible=false`；`StageWorkspaceScreen` 通过 `AnimatedVisibility(state.railVisible)` 控制左栏 | 默认隐藏；截图无左栏是当前代码逻辑的直接结果 |
| 横屏不能直接点击切换 | `StageHostActivity` 有组点击回调和 Overlay tap target，但前提是 railVisible；Dock 里只有一个“应用组”开关 | 基础切换函数存在，但用户入口默认被隐藏 |
| 横竖屏布局没有完整差异化 | 活动 `StageWorkspace.computeLayout()` 固定 dockH=84dp、railWidth=238dp、workspace 左右 18dp；另一个 `StageLayoutEngine` 有 orientation 分支，但由 `StageRuntime` 使用，不等于 StageWorkspace 已采用 | 必须统一布局引擎，不能让两个布局模型各自计算 |
| 跨组拖动未闭环 | `moveWindowToGroup()` 仅更新模型和同步几何；MILESTONES 也注明跨组拖动没有手势 | 必须实现从左栏到中央、中央到左栏、组卡片之间的拖放 |
| 最小化不等同于 iPad 行为 | 当前最小化把 Task 移到 StageHost 后面，并出现在底部 MinimizedTray | 应改为从当前组移除并回到最近列表，保留任务 |
| Dock 不像 iPad | `DockApps.kt` 使用硬编码优先应用列表；StageDock 只显示前 6 个、应用库和退出按钮 | 缺少用户固定 Dock、最近/建议区、活动指示和完整长按菜单 |
| 缺少 App Exposé | 没有按应用枚举/展示多个窗口的 UI 流程 | 需要新增 |
| 缺少 New Window 菜单 | 当前 Dock 长按仅拖动；没有应用上下文菜单 | 需要按应用支持能力实现 |
| 缺少完整窗口控制 | 当前只有红色关闭和黄色最小化，没有 Zoom/Full Screen/长按更多选项/双击顶部缩放 | 需要补齐 |
| 缺少底部任务切换手势 | 目前实现左边缘唤出栏，未见底边滑动切组/上滑 Exposé | 需要逐项实现并处理系统手势冲突 |
| Dock 自动隐藏缺失 | Dock 当前固定显示 | 需要配置与底边缘唤出 |
| 系统菜单栏缺失 | 没有全局菜单栏/Window 菜单 | P2 扩展，需标记 Android 限制 |
| 外接显示器未验证 | 没有独立 display workspace | P2，不列入首轮核心 |

### 8.3 特别注意

- 当前 `StageWorkspaceScreen` 的根容器点击空白时调用 `setRailVisible(false)`，不能让“点一下空白”意外关闭默认工作台栏；应明确区分“点击工作区空白”“窗口输入”“边缘手势”。
- 目前左栏点击由 Overlay 接管，因为真实预览 Task 在 StageHost 上方；继续使用 Overlay 时，必须限定触摸区域，不能吞掉窗口内容触摸。
- 当前窗口圆角不能只给 Compose 背景和标题栏加 `RoundedCornerShape`。真实 Task Surface 是独立系统窗口，必须验证 SurfaceControl/WMS 圆角或无触摸遮挡的角落遮罩方案。
- 当前横屏模型在 `StageModels.kt` 与 `StageWorkspace.kt` 存在两套计算逻辑；应让实际 StageHost、Task bounds、Rail、Dock 共用同一 LayoutSpec。

## 9. 实施顺序与验收门槛

### P0：行为规格与 UI 基准冻结

- 先阅读本文和当前所有代码。
- 输出功能矩阵：iPad 官方行为、当前 StageLab 状态、目标实现、测试方法。
- 用用户上传的最新竖屏截图作为当前缺陷基线。
- 建立横屏目标布局图/尺寸规范；不要先写一堆 UI 再补逻辑。

### P1：窗口真实圆角与窗口 chrome

- 为真实 Task 内容实现四角圆角。
- 焦点/非焦点边框、阴影、标题栏、控制点保持一体。
- 真实窗口内容不得方角露出。
- 触摸、IME、Back、无障碍不受损。
- 必须真机检查不同背景色应用、视频、状态栏/导航栏、透明窗口。

### P2：横屏工作台与点击切换（用户当前最高优先级）

- 横屏默认显示左侧最近工作台列表。
- 至少创建三个工作台，每个含不同应用组合。
- 用户直接点击左侧卡片即可切换。
- 旧组移入最近列表，目标组进入中央工作区。
- 任务 ID、窗口位置、z-order、应用状态保持。
- 工作台卡片不能被真实 Task 覆盖而无法点击。
- 竖屏使用适配布局，但不牺牲横屏完整功能。

### P3：组拖放闭环

- Dock → 当前组。
- 左侧最近组 → 当前组。
- 当前组窗口 → 左侧最近组（移出组）。
- 当前组窗口 → 另一组。
- 拖放过程中显示目标高亮与吸附动画。
- 松手后系统 Task 和 Session 数据必须一致。

### P4：窗口控制和操作完整性

- 四角圆角、拖动、四边/四角缩放。
- Zoom/Full Screen/Restore。
- Minimize 回到最近组。
- Close 只关闭选中窗口。
- 长按控制菜单。
- 双击顶部缩放（设置可开关）。
- 窗口前后层级和焦点管理。

### P5：Dock 和应用窗口能力

- 可配置固定应用。
- 最近/建议应用。
- App Library。
- 长按应用菜单。
- New Window（应用支持时）。
- App Exposé / Show All Windows。
- Dock 自动隐藏/唤出。

### P6：系统手势和高级能力

- 左侧最近组自动隐藏与边缘唤出。
- 底部 Dock 唤出。
- 底边切换组。
- 上滑停顿的工作台/窗口概览。
- 多指手势（与 Android 系统导航冲突时采用可行替代）。
- 键盘/鼠标/触控板。
- 可选菜单栏和外接显示器研究。

### P7：动画、性能和兼容性

- 真实 Task 窗口位移/缩放动画，而非只动画 Compose chrome。
- 组切换动画。
- 窗口拖动跟手、边缘吸附和层级变化。
- 120Hz 下流畅性。
- 视频、浏览器、聊天、便签、WebView、DRM/FLAG_SECURE。
- 一小时长稳、内存和 Surface 泄漏。

## 10. 验收证据规则

每个功能必须明确区分：

1. 已写代码；
2. 已编译；
3. 模拟器通过；
4. ADB 自动化通过；
5. OPPO Pad mini 真机手动通过；
6. 第三方应用兼容通过。

不能以“函数存在”“模型字段存在”或“测试靶通过”宣称完整功能。

至少建立以下真机测试场景：

- 横屏：左栏常驻，点击三个不同工作台来回切换。
- 每个工作台有 2–3 个真实窗口，窗口位置和层级在切换后恢复。
- 从 Dock 拖入应用、从左栏拖入窗口、从中央拖出窗口到左栏。
- 圆角：窗口四角没有方形内容泄漏，真实触摸在窗口边缘正常。
- 窗口最小化后回到左侧最近列表，不出现在一个与 iPad 不同的独立“任务芯片托盘”中。
- Dock 点击/长按/拖放/应用库/最近应用。
- 横竖屏旋转后布局和窗口几何恢复。
- 触摸、IME、Back、无障碍和系统导航不回归。
